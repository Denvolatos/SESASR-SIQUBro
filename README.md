## 1️⃣ R01 — Bump&Go controller / Bump&Go 控制器

**EN** — The robot always drives straight ahead. When the LiDAR sees a wall closer than 0.5 m, it stops, compares the free space on the left and on the right, and turns towards the more open side using the odometry yaw (90° in simulation; on the real robot it stops turning as soon as the way is free). The same code runs on the real TurtleBot3 with its own parameter file (`config/real_robot.yaml`).

**中文** — 小车一直往前走；激光雷达发现前方 0.5 m 内有墙时停下，比较左右哪边更空，用里程计的偏航角转向更空的一侧（仿真里转 90°；真车上前方一空出来就停止转向）。同一份代码在真车上运行，使用自己的参数文件（`config/real_robot.yaml`）。

```bash
ros2 launch lab02_pkg bump_and_go.launch.py              # simulation (start the Lab02 world first) · 仿真，需先启动 Lab02 场景
ros2 launch lab02_pkg bump_and_go.launch.py robot:=real  # real robot · 真车
```

Final code in the Lab02 maze: goal reached after 10 turns in 220 s; odometry error vs ground truth 0.069 m at the end, 0.073 m maximum. On the real robot the speed limit is 0.15 m/s: at 0.22 m/s it hardly drove forward.
最终版代码在 Lab02 迷宫：转弯 10 次、220 秒到达终点；里程计相对真实位置的误差结束时 0.069 m，最大 0.073 m。真车速度上限为 0.15 m/s：0.22 m/s 时基本不前进。

## 2️⃣ R02 — EKF localization / EKF 定位

**EN** — An extended Kalman filter estimates the robot pose. It predicts at 20 Hz with the velocity motion model, using v and ω from `/odom`, and corrects the estimate with the range and bearing of each landmark it sees. With `fusion:=true` the state also contains v and ω, which are corrected by `/odom` and `/imu`. The result is published on `/ekf`.

**中文** — 用扩展卡尔曼滤波估计小车位姿：以 20 Hz 用速度运动模型预测（v、ω 取自 `/odom`），每看到一个地标就用它的距离和方位修正。`fusion:=true` 时状态里还包括 v、ω，由 `/odom` 和 `/imu` 修正。结果发布在 `/ekf`。

```bash
ros2 launch turtlebot3_ignition lab04.launch.py      # simulation world (Mac: ignition) · 仿真场景
ros2 launch lab04_pkg ekf.launch.py                  # Task 1: state [x, y, θ]
ros2 launch lab04_pkg ekf.launch.py fusion:=true     # Task 2: state [x, y, θ, v, ω]
ros2 launch lab04_pkg ekf.launch.py robot:=real      # Task 3: real robot, landmarks on /camera/landmarks
```

Simulation, 150 s runs, Bump&Go moving the robot (position RMSE against the ground truth): / 仿真，每次 150 秒，用 Bump&Go 让车动（相对真实位置的位置 RMSE）：

| Run / 实验 | `/odom` | `/ekf` |
|---|---|---|
| Task 1 | 0.018 m | 0.010 m |
| Task 2 | 0.020 m | 0.010 m |

On the same recorded data, Task 2 reduced the heading error by about 20–30 % but did not improve the position. These numbers come from one simulated run each; the course metrics tool gives the same values (within 0.5 mm). / 在同一份数据上回放时，Task 2 的航向误差小约 20–30%，位置没有改善。以上数字各来自一次仿真运行；用课程提供的指标工具算出的结果相同（差 < 0.5 mm）。

It checks the robot topics, builds the package, starts the EKF with the landmarks of the day and records a bag in `~/g203_bags/`; Ctrl+C stops everything cleanly. **Real robot / 真车（19 Nov 2026, robot 3）：** the robot started at the map origin, the cross on the floor (0, 0, 0). With the Task 2 filter, a 172 s drive around the obstacles saw 7 of the 9 tags, and at the end `/ekf` and `/odom` were 0.28 m apart. There is no ground truth on the real robot, so this only shows that the two estimates agree with each other and with the tag measurements, not how accurate they are. / 小车从地图原点（地上的十字，(0, 0, 0)）出发。用 Task 2 滤波器绕障碍物开了 172 秒，9 个地标看到 7 个，结束时 `/ekf` 与 `/odom` 相差 0.28 m。真车没有真实位置可比，所以这只说明两者彼此一致、并与地标观测相符，不代表绝对精度。

Things we learned on the robot / 真车上的经验：
- The tags are moved for every lab session: use the `tag_positions.txt` of the day (`LANDMARKS=...`). `config/landmarks_thu1211.yaml` is only the arena of 12 Nov. / 每次实验课地标位置都不同，要用当天的 `tag_positions.txt`；`config/landmarks_thu1211.yaml` 只是 11/12 的场地。
- With a wrong start pose and only one tag in view, the position has two solutions: in one run the filter first settled on the wrong one and jumped to the right one 44 s later, when more tags came into view. Start where the camera sees two or more tags. / 起点填错、又只看得到一个地标时，位置有两个解：有一次滤波器先停在错误的解上，44 秒后看到更多地标才跳回正确位置。起步时最好能看到两个以上地标。
- The robot PC has no internet: copy the code to it (`scp`) instead of `git clone`. Changing the battery restarts the whole robot, so all four launches have to be started again. / 车上的电脑不能上网，代码要用 `scp` 拷过去；换电池会让整台车重启，四个程序都要重开。

## 3️⃣ R03 — DWA obstacle avoidance and target following / DWA 避障与目标跟随

**EN** — A Dynamic Window Approach controller runs at 15 Hz. It samples (v, ω) inside the dynamic window, simulates each trajectory for 1.5 s and scores it with J = α·heading + β·vel + γ·dist_obst; trajectories that would come too close to an obstacle are removed first. Obstacles come only from the LiDAR, reduced to 24 sectors (NaN, Inf and zero readings are handled, single-ray spikes are removed with a 3-point median). An independent laser safety stop ends the run with `Collision`. For Task 2 (following a moving target) the score also has vel′ (slow down near the target) and dist_target (keep about 0.8 m and the target in the camera view). Results are published on `/nav_result` (`Goal`, `Collision`, `Timeout`, `Lost`).

**中文** — DWA 控制器以 15 Hz 运行：在动态窗口里采样 (v, ω)，每条轨迹向前模拟 1.5 秒，用 J = α·heading + β·vel + γ·dist_obst 打分；离障碍太近的轨迹先剔除。障碍只来自激光雷达，压缩成 24 个扇区（处理 NaN、Inf 和 0，三点中值滤掉单条射线的毛刺）。另有一个独立的激光急停，触发时结果为 `Collision`。Task 2（跟随移动目标）在打分里加上 vel′（接近目标时减速）和 dist_target（保持约 0.8 m、目标在摄像头视野里）。结果发布在 `/nav_result`（`Goal`、`Collision`、`Timeout`、`Lost`）。

```bash
ros2 launch turtlebot3_ignition project.launch.py           # simulation world · 仿真场景
ros2 launch lab07_pkg dwa.launch.py                         # Task 1: static goal on /goal_pose
ros2 launch lab07_pkg dwa.launch.py mode:=follow            # Task 2: follow /dynamic_goal_pose
ros2 launch lab07_pkg dwa.launch.py robot:=real             # Task 3: real robot, static goal
ros2 launch lab07_pkg dwa.launch.py robot:=real mode:=follow target_id:=N   # Task 3: follow AprilTag N
```

Send a goal / 发目标：`ros2 topic pub --once /goal_pose geometry_msgs/msg/PoseStamped "{header: {frame_id: odom}, pose: {position: {x: 1.5, y: -0.5}}}"`

Simulation (course world `hard_maze.world`, robot starting at the origin) / 仿真（课程地图，车从原点出发）：
- **Task 1:** 8 goals × 3 runs: 24 / 24 reached, no collision. Four other goals behind the central walls end in `Timeout`: the robot is caught in a local minimum, a known limit of DWA. / 8 个目标各 3 次：24 / 24 到达，无碰撞。另有 4 个在中间墙后面的目标会 `Timeout`：车陷入局部极小，这是 DWA 已知的局限。
- **Task 2:** on the course trajectory of the red cube, 3 / 3 runs followed the whole first lap (about 21 m) with no collision. The cube cuts a corner 0.115 m from a wall, so the robot falls behind there (up to 3.5–4.9 m) and then catches up; mean distance over the lap 2.0–2.8 m. / 在课程给定的红色方块路线上，3 / 3 次跟完第一圈（约 21 m），无碰撞。方块在离墙 0.115 m 处切过墙角，车在那里会落后（最多 3.5–4.9 m），之后再追上；整圈平均距离 2.0–2.8 m。

Tools in `src/lab07_pkg/scripts/` / 工具：`evaluate_nav.py` (success rate, time, path length, obstacle distance, velocity and trajectory plots from a bag) · `run_goal_trials.sh` + `run_single_trial.py` (repeated Gazebo trials) · `offline_sim.py` (pure-Python simulation for quick tests, not a replacement for Gazebo).
